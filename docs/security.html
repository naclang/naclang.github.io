Cookies, sessions and security.

Inside a route, cookie is a map of request cookie names to values, so Cookie: sid=abc; theme=dark becomes cookie.sid and cookie.theme. Values are kept raw (not URL-decoded); call urlDecode() when needed.

Set cookies from inside a route. Each call appends one Set-Cookie header to the current response (at most 16 per response):

cookies.nacNaC
route POST "/login" {
    sid = sessionId()                    // 32 random bytes, base64url (43 chars)
    setCookie("sid", sid, {
        path: "/",
        httpOnly: true,                  // default true
        secure: false,                   // true behind HTTPS
        sameSite: "Lax",                 // "Lax" (default), "Strict", "None", or false
        maxAge: 86400                    // seconds; omitted by default
    })
    return json({ ok: true })
}

route POST "/logout" {
    clearCookie("sid", { path: "/" })
    return json({ ok: true })
}

Cookie defaults: path: "/", httpOnly: true, secure: false, sameSite: "Lax", and no Max-Age/Expires. sameSite: "None" automatically turns on Secure. clearCookie emits Max-Age=0 and an Expires date in the past. Names must be HTTP tokens and values may not contain ; or control characters. Invalid input returns false and reports an error: it is catchable in try, otherwise the script exits nonzero. expires (an HTTP date string) and domain are also accepted.

Security primitives

Built in, no imports:

Function Result
randomBytes(n) 2*n lowercase hex characters from a CSPRNG; n is 1..4095.
uuid() Random (v4) UUID string.
sessionId() 32 random bytes as 43-character base64url text.
sha256(s) SHA-256 of s as 64 lowercase hex characters.
hmac(key, message) HMAC-SHA256 as 64 lowercase hex characters.
base64Encode(s) / base64Decode(s) Standard base64 with = padding.
safeEqual(a, b) Byte-wise constant-time for equal-length strings; the loop is bounded by the shorter length. Returns a bool.
passwordHash(password) Salted PBKDF2-HMAC-SHA256 string.
passwordVerify(password, hash) Constant-time check against a passwordHash value.

Password hashes look like pbkdf2-sha256$<iterations>$<salt_b64>$<hash_b64> (random 16-byte salt, 210,000 iterations, 32-byte key). The cost can be raised later without invalidating existing hashes.

JWT

jwtSign(payload, secret) signs a claims map as an HS256 token. Include time claims such as exp yourself; now() returns seconds since the Unix epoch.

jwt.nacNaC
secret = env("JWT_SECRET")
token = jwtSign({ sub: "ada", exp: now() + 3600 }, secret)
claims = jwtVerify(token, secret)       // claims map, or null

jwtVerify(token, secret) verifies HS256 signatures and returns the claims map, or null for a malformed token, invalid signature, expired exp or future nbf. Times are in seconds and are checked without leeway. Keep the signing secret outside source code and use a strong random value.

Sessions

There is no hidden session store: generate the ID on the server, keep it in a global map, and carry it in an HttpOnly cookie. The cookie value alone is not trusted; look it up and check expiry on every request.

sessions.nacNaC
sessions = {}                            // sid -> { username, expires }
SESSION_TTL = 86400

route POST "/login" {
    // ... verify the password with passwordVerify(...)
    sid = sessionId()
    sessions[sid] = { username: user.username, expires: now() + SESSION_TTL }
    setCookie("sid", sid, { maxAge: SESSION_TTL, httpOnly: true, sameSite: "Lax" })
    return json({ ok: true })
}

route GET "/me" {
    sid = cookie.sid
    if isNull(sid) or type(sid) != "string" or sid == "" {
        return json({ error: "authentication required" }, 401)
    }
    s = sessions[sid]
    if isNull(s) or s.expires <= now() {
        return json({ error: "authentication required" }, 401)
    }
    return json({ username: s.username })
}

See examples/web/06_accounts.nac for register/login/logout, protected routes, role checks and a JSON-file user store.

Server hardening (always on)

Limit Default
Request header block 16 KiB, else 431
Request body 1 MiB (configurable up to 64 MiB), else 413
Whole-request read deadline 10 seconds, else 408
Requests per client IP 120 per 60-second fixed window, else 429 + Retry-After
Concurrent connections 64

Every dynamic and static response also carries X-Content-Type-Options: nosniff, X-Frame-Options: DENY and Referrer-Policy: no-referrer. Response header names or values containing CR/LF are dropped, so a script-supplied value cannot inject extra headers.

Behind a reverse proxyThe rate limiter uses the socket address, not X-Forwarded-For, so behind a reverse proxy every request looks like it comes from the proxy.
