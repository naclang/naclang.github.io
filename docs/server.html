HTTP server.

server.nacNaC
static("public")                       // "/" -> public/index.html, /app.css -> public/app.css
static("/assets", "public/assets")     // mount a directory under a URL prefix

route GET "/hello/:name" {
    return html(`<h1>Hello, ${params.name}!</h1>`)
}

route POST "/api/users" {
    data = jsonParse(body)
    return json(data, 201)
}

serve(8080)                            // blocking

route METHOD "pattern" { ... }: METHOD is GET, POST, PUT, PATCH, DELETE, ... or * for any. Inside the body you have method, path, query, headers, body, params and cookie (see cookies).

  • :name captures a path segment into params.name (URL-decoded); a trailing * captures the rest into params["*"]. Routes are tried in declaration order.
  • At most 128 routes.

static(dir) / static(prefix, dir) serves GET/HEAD from a directory; directory URLs serve index.html; the MIME type comes from the extension; .. is rejected. Files can be up to 32 MB; up to 8 mounts.

Request flow: the built-in /health is answered before rate limiting (a script's own GET /health route takes precedence); requests rejected before script handling (400, 408, 413, 429, 431) never reach routing. Otherwise rate limiting runs, routes are matched, before blocks may short-circuit, the matched route runs, then static mounts, then the legacy serve(port, "handler") fallback, and finally 405 (the path matches a route for another method) or 404.

Responses

A route returns a string (200; text/html if it starts with <, else text/plain), a map with status, body and headers, or one of:

responses.nacNaC
html(body)        html(body, status)
json(value)       json(value, status)       // application/json
redirect(url)     redirect(url, status)     // 302 by default

Dynamic bodies and header values grow with available memory. Handlers run one at a time, so a slow route delays the others.

Request helpers

Function Result
form(body) Parses an application/x-www-form-urlencoded request body into a map.
header(name, value) A map holding that one response header.
setHeader(name, value) / setHeader(headers) Adds one response header or a map of headers to the current response, including responses from static files.
cors(origin, methods, headers) A map of CORS response headers for the origin, the allowed methods and the allowed request headers.
request-helpers.nacNaC
ORIGIN = "http://localhost:3000"

route OPTIONS "/api/greet" {                      // CORS preflight
    return {
        status: 204,
        body: "",
        headers: cors(ORIGIN, "POST, OPTIONS", "Content-Type")
    }
}

route POST "/api/greet" {
    data = form(body)
    if not ("name" in data) or data.name == "" {
        return json({ error: "name is required" }, 400)
    }

    headers = cors(ORIGIN, "POST, OPTIONS", "Content-Type")
    extra = header("X-NaC-Example", "request-helpers")
    headers["X-NaC-Example"] = extra["X-NaC-Example"]
    headers["Content-Type"] = "application/json; charset=utf-8"

    return {
        status: 200,
        body: jsonStringify({ message: "Hello, " + data.name }),
        headers: headers
    }
}

Middleware

before blocks run after route matching but before the route handler; after blocks run after a response is produced. Blocks run in declaration order, with up to 32 registered blocks.

middleware.nacNaC
before "/admin/*" {
    if (headers.authorization or "") != "Bearer " + env("ADMIN_TOKEN") {
        return json({ error: "unauthorized" }, 401)
    }
}

after {
    setHeader(cors("*"))
    print(`${method} ${path} -> ${response.status}`)
}

An unfiltered before block runs for every request. Use before "pattern" to limit it to matching paths. A before block can read the request fields (method, path, query, headers, body, params, cookie), including the params already captured by route matching; returning a response short-circuits the route. An after block also receives response (status, body, headers) and may return a replacement. Middleware does not run for requests rejected before script handling (400, 408, 413, 429, 431), or the built-in /health endpoint.

Templates

render(path, values) fills the {{ name }} placeholders of an HTML file. Values are HTML-escaped, so user input cannot inject markup. It returns an HTML response, so a route can return it directly. In the examples the path is relative to the project root, where the server is started.

templates.nacNaC
// examples/web/templates/greeting.html
//   <h1>Hello, {{ name }}!</h1>

route GET "/hello/:name" {
    return render("examples/web/templates/greeting.html", {
        title: params.name,
        name: params.name
    })
}

Configuration

At startup NaC loads a .env file from the working directory if there is one. Variables that are already set in the process environment take precedence over the file.

  • env("PORT", "8080") returns the default only when PORT is not set.
  • serve() without a port uses PORT and falls back to 8080.
  • An explicit serve(port) overrides the configured value.
  • serve(port, host) can also select the bind host. Command-line --port and --host override the script; --port takes priority over serve(port).
.envdotenv
PORT=8081
config.nacNaC
route GET "/" {
    return json({ message: "Configuration loaded", port: env("PORT", "8080") })
}

serve()      // PORT from .env or the environment, else 8080

Server options

Pass these flags to nac or the built executable; each may also be set with the listed environment variable. Command-line values take precedence. Numeric ranges are inclusive.

Flag Environment Default Meaning
--host ADDR NAC_HOST 0.0.0.0 IPv4 bind address or hostname.
--port N PORT 8080 Listen port, 1–65535.
--max-connections N NAC_MAX_CONNECTIONS 64 Open connections, 1–4096.
--workers N NAC_WORKERS 8 Request worker threads, 1–256 (Unix; Windows uses a thread per connection).
--read-timeout-ms N NAC_READ_TIMEOUT_MS 10000 Whole-request read deadline, 100–600000 ms.
--max-header-bytes N NAC_MAX_HEADER_BYTES 16384 Header-block limit, 1024–32768 bytes.
--max-body-bytes N NAC_MAX_BODY_BYTES 1048576 Request-body limit, up to 67108864 bytes (64 MiB).
--rate-limit N NAC_RATE_LIMIT_MAX 120 Requests per client IP per window; 0 disables the limiter.
--rate-window-sec N NAC_RATE_LIMIT_WINDOW_SEC 60 Rate-limit window, 1–86400 seconds.
--health NAC_HEALTH off Enable built-in GET/HEAD /health, returning 200 and {"status":"ok"}. A script's GET /health route takes precedence.
--shutdown-timeout-ms N NAC_SHUTDOWN_TIMEOUT_MS 10000 Graceful shutdown wait, 0–600000 ms; 0 exits without waiting.

For example, ./nac --host 127.0.0.1 --port 8080 --health app.nac listens only on loopback and enables the health probe.

Deployment

NaC speaks plain HTTP. For HTTPS, put a reverse proxy in front of it: the proxy terminates TLS and renews certificates, while NaC listens on loopback. Flags can appear anywhere on the command line and are not passed to the script; use -- to pass the rest through untouched.

terminalbash
./nac --host 127.0.0.1 --port 8080 --health app.nac
./app --host 127.0.0.1 --port 8080 --health         # built with nac build

Priority is command line, then the environment (including .env), then the default. For the port and host: --port beats serve(port), which beats PORT, which beats 8080; --host beats serve(port, host), which beats NAC_HOST. HOST is deliberately ignored because some shells export it as the machine name. Bad values stop the server at startup with a clear message.

--health (or NAC_HEALTH=1) adds GET/HEAD /health returning 200 and {"status":"ok"}. It is exempt from rate limiting. A script’s own route GET "/health" takes precedence, which lets you report database status instead.

Caddy

CaddyfileTLS at the proxy
example.com {
    encode gzip
    request_body {
        max_size 8KB
    }
    reverse_proxy 127.0.0.1:8080 {
        health_uri /health
        health_interval 10s
    }
}

nginx

Get a certificate (for example sudo certbot certonly --nginx -d example.com), then:

nginx.confTLS at the proxy
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    client_max_body_size 1m;        # match --max-body-bytes

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}

NaC keeps HTTP/1.1 connections alive (idle ones close after a few seconds). An idle connection is watched by one poll() thread and only occupies a worker while a request is read and handled, so --max-connections can be much larger than --workers. In nginx, enable HTTP/1.1 and an upstream keep-alive pool:

nginx.confkeep-alive
upstream nac {
    server 127.0.0.1:8080;
    keepalive 32;
}

location / {
    proxy_pass http://nac;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
}

Behind a proxy the rate limiter still sees the proxy’s socket address, not X-Forwarded-For; configure the limiter with that in mind.
