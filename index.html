NaC / web servers

A small language for web servers.

NaC turns a file of routes into an HTTP server. Static files, JSON, cookies, sessions and an HTTP client are part of the language. So are the request limits and security headers.

01 / Why NaC

The web parts are in the language.

An endpoint, a static folder, JSON in and out, an outgoing API call, a login cookie. NaC keeps those close and leaves the framework stack behind.

Web-first syntax

route, static and serve are keywords. Path parameters, query strings, headers, bodies and cookies arrive as maps.

JSON in, JSON out

jsonParse(body) reads a request; json(value, status) writes a response with the right content type. Validation is a normal if.

Outgoing HTTP included

Call another service with http.get { url: ... }, add headers and timeouts, or attach a callback. A failed request is a value, not a crash.

Security built in

HttpOnly cookies, server-side session IDs, PBKDF2 password hashing, SHA-256, HMAC, base64 and a CSPRNG are standard builtins.

Safer defaults

Header and body limits, a request deadline, per-IP rate limiting, security headers and CR/LF header-injection protection are on without configuration.

One small binary

./nac build app.nac bundles your script and the runtime into a standalone executable. Deployment is copying a file.

03 / Security

Security is not an add-on.

NaC ships the pieces a small backend needs: random IDs, password hashing, HMAC, constant-time comparison and cookies with safe defaults. Sessions stay explicit; you own the table, NaC gives you the primitives.

Sessions and cookies

  • cookie.name reads request cookies; setCookie emits one Set-Cookie header per call.
  • sessionId() returns 32 random bytes as base64url. passwordHash uses 210,000 PBKDF2 rounds.

Safe defaults

  • sameSite: "None" turns on Secure automatically; HttpOnly is on by default.
  • Response header names or values containing CR/LF are dropped, preventing header injection.
Security and sessions
login.nac session cookie 
route POST "/login" {
    data = jsonParse(body)
    user = findUser(data.username)
    if isNull(user) or not passwordVerify(data.password, user.password) {
        return json({ error: "invalid credentials" }, 401)
    }

    sid = sessionId()
    sessions[sid] = { username: user.username, expires: now() + 86400 }
    setCookie("sid", sid, {
        httpOnly: true,
        sameSite: "Lax",
        maxAge: 86400
    })
    return json({ ok: true })
}

Hardening defaults

Applied without configuration. TLS stays at the reverse proxy.

8191 B request body, then 413
16 KiB header block, then 431
10 s read deadline, then 408
120 / min per IP, then 429

04 / Quick start

Build it, run it, call it.

Windows uses build.bat and nac.exe. The commands below are the Unix path; the language is the same on both.

terminal bash 
git clone https://github.com/naclang/nac.git
cd nac
./build.sh                      # build.bat on Windows
./nac examples/web/01_hello.nac

# in another terminal
curl "http://localhost:8080/hello?name=Ada"
curl http://localhost:8080/users/1
